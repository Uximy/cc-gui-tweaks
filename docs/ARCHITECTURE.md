# Как устроен CC GUI Tweaks

Плагин состоит из двух половин:

- **Java** (`src/local/ccguitweaks/`) работает внутри IDE. Она ищет браузеры, хранит настройки и ходит в сеть
  (Spotify, Anthropic, LRCLIB), запускает хелпер и пишет журнал.
- **JavaScript** (`resources/cc-gui-tweaks/tweaks.js`) работает на странице чата CC GUI. Он рисует плеер,
  бар лимитов, панель текста, раздел настроек и следит за кадрами.

Половины общаются через консоль браузера в одну сторону и через `executeJavaScript` в другую.
CC GUI при этом не меняется: ни его JAR, ни его файлы.

```
           IDE (Java)                                         страница CC GUI (JCEF)
 ┌────────────────────────────┐   executeJavaScript(tweaks.js)   ┌──────────────────────────┐
 │ Tweaks: раз в 2 с ищет     │ ───────────────────────────────▶ │ tweaks.js                │
 │ JBCefBrowser в окнах IDE   │                                  │  isCcGui()? → send(ready)│
 │                            │ ◀─── console: "__cct:ready" ──── │                          │
 │ onConsoleMessage → onMessage│ ◀── "__cct:set:{...}" и др. ──── │ send('...')              │
 │                            │ ── window.__cct.settings(json) ─▶│ onSettings / onSpotify / │
 │ модули: Spotify, Limits,…  │ ── window.__cct.spotify(json) ──▶│ onLimits / …             │
 └────────────────────────────┘                                  └──────────────────────────┘
        │ HTTP localhost:43117
        ▼
   helper.ps1 (PowerShell): SMTC Windows + микшер громкости
```

## Жизненный цикл

1. **`Starter`** подписан в `plugin.xml` на `AppLifecycleListener.appStarted`, а также на
   `DynamicPluginListener.pluginLoaded / beforePluginUnload`. Поэтому плагин запускается и при старте IDE,
   и при установке или обновлении без перезапуска.
2. **`Tweaks.start()`** загружает `tweaks.js` из ресурсов и читает настройки (`Settings.load`). Затем включает
   Swing-таймер `scan()` раз в 2 с и вызывает `apply()` у модулей (`SpotifyModule`, `LimitsModule`,
   `PerfJournal`) и `Updater.start()`.
3. **`scan()`** обходит окна IDE и ищет компоненты с client property `"JBCefBrowser.instance"`.
   В каждый новый браузер он вешает `CefLoadHandler`, который внедряет скрипт после каждой загрузки страницы,
   и `CefDisplayHandler`, который ловит сообщения консоли. Скрипт внедряется во **все** JCEF-браузеры, а
   `tweaks.js` сам проверяет, что это CC GUI (`isCcGui()`: есть `#app` и CSP с `cc-gui` или заголовок «Claude Chat»).
   На чужих страницах он ничего не делает.
4. Страница отвечает `__cct:ready`. В ответ Java присылает ей настройки, а модули присылают свежие данные
   (`onReady(b)` у каждого модуля).
5. **`Tweaks.stop()`** вызывается при выгрузке. Он останавливает таймеры и модули, снимает обработчики JCEF и
   вызывает на страницах `window.__cctStop()`, который убирает всё добавленное (стили, элементы, слушатели).
   Хелпер Spotify при этом не останавливается: его подхватит новая версия плагина.

## Канал «страница → Java»

Бандл CC GUI заменяет `console.log/info/warn` пустышками, поэтому `send()` пишет через `console.context()`.
Это отдельный нативный объект консоли, и подмены его не касаются. Если `console.context` нет, используется
`console.error`. Все сообщения начинаются с префикса `__cct:`, их разбирает `Tweaks.onMessage`:

| Сообщение | Кто обрабатывает | Что делает |
|---|---|---|
| `ready` | `Tweaks` | страница готова: прислать настройки и данные модулей |
| `set:{json}` | `Settings.update` | новые настройки целиком; Java берёт из них только известные ключи и рассылает результат всем страницам |
| `spotify:toggle` / `next` / `prev` / `vol:N` / `seek:ms` / `mute:0\|1` | `SpotifyModule.command` | команды плееру через хелпер; при перетаскивании громкости и перемотки отправляется только последнее значение |
| `spweb:login` / `logout` / `queue` / `play:…` / `open:…` / `dashboard` / `copy` | `SpotifyWeb.command` | вход в Spotify Web API, очередь, запуск трека, открытие в Spotify |
| `lyrics:{t,a,al,d}` | `Lyrics.request` | найти текст трека |
| `limits:refresh` | `LimitsModule.refreshSoon` | обновить лимиты сейчас |
| `reg:set:…` / `reg:reset:…` / `reg:resetall` / `reg:restart` | `RegistryTweaks.command` | ключи реестра встроенного браузера, перезапуск IDE |
| `perflog:[...]` | `PerfJournal.append` | пачка событий журнала со страницы (не больше 60 за раз) |
| `journal:export:{meta}` / `clear` / `reveal` / `get` | `PerfJournal.command` | выгрузить zip, очистить журнал, показать файл |
| `open:github` / `open:site` | `Tweaks` | ссылки с вкладки «О плагине»; страница передаёт ключ, а не URL |

## Канал «Java → страница»

Java вызывает функции объекта `window.__cct`, который создаёт `tweaks.js`. `Tweaks.exec` шлёт вызов одной
странице, `Tweaks.broadcast` всем. Данные передаются JSON-аргументом.

| Вызов | Откуда | Данные |
|---|---|---|
| `__cct.settings(s)` | `Settings.forPage` | все настройки + `meta.version` |
| `__cct.spotify(d, cover)` | `SpotifyModule` | трек, исполнитель, позиция, длительность, играет ли, громкость, обложка |
| `__cct.spotifyWeb(w)` | `SpotifyWeb` | вошли ли в Web API, ошибка входа |
| `__cct.queue(d)` | `SpotifyWeb` | очередь и контекст (плейлист, альбом, исполнитель) |
| `__cct.lyrics(d)` | `Lyrics` | `{t,a,found,synced:[[ms,txt]],plain,inst,err}` |
| `__cct.limits(d)` | `LimitsModule` | проценты и время сброса окон, ошибка, когда повторить |
| `__cct.registry(d)` | `RegistryTweaks` | значения ключей, изменены ли они относительно умолчания, ждут ли перезапуска |
| `__cct.journal(d)` | `PerfJournal` | `{on,lags,since,size,busy,saved,err}` |

## Настройки (`Settings.java`)

Настройки лежат одной JSON-строкой в `PropertiesComponent` уровня приложения (ключ `ccGuiTweaks.settings`,
файл `options/other.xml` в конфиге IDE), поэтому переживают перезапуск. При чтении сохранённое
накладывается на значения по умолчанию. Поэтому новый ключ сразу получает своё значение по умолчанию.
Страница присылает объект целиком, а `update` берёт только известные ключи нужного типа. Строки принимаются
только из латиницы и цифр: это Client ID Spotify.

| Модуль | Ключ | По умолчанию | Смысл |
|---|---|---|---|
| `spotify` | `enabled` | `false` | показывать плеер |
| | `time`, `volume` | `true` | время трека, регулятор громкости |
| | `queue` | `false` | кнопка очереди (Web API) |
| | `clientId` | `""` | Client ID приложения Spotify пользователя |
| | `size` | `1` | 1 — обычный плеер, 2 — крупный |
| | `lyrics` | `false` | кнопка «Текст песни» |
| | `collapsed` | `false` | плеер свёрнут в значок |
| `limits` | `enabled` | `false` | показывать бар лимитов |
| | `models`, `resets` | `true` | лимиты по моделям, время сброса |
| | `interval` | `60` | как часто спрашивать, секунд |
| `perf` | `enabled` | `false` | режим производительности |
| | `anim`, `blur` | `true` | глушить бесконечные анимации, убрать размытие |
| | `journal` | `false` | журнал лагов (работает и без `enabled`) |

Правило проекта: **каждый модуль имеет свои настройки, по умолчанию выключен, а включённое состояние
сохраняется после закрытия IDE.**

## Модули на стороне Java

### `SpotifyModule`: плеер
- При включении он распаковывает `helper.ps1` в `<system>/cc-gui-tweaks/` и запускает
  `powershell -NoProfile -ExecutionPolicy Bypass -WindowStyle Hidden`.
- Затем раз в 1,5 с опрашивает `GET /now` и рассылает результат страницам. Обложку берёт через `GET /cover?k=…`.
- При выключении шлёт `POST /quit`. Если хелпер никто не спрашивает 90 с (например, IDE закрыли), он выходит сам.

### `helper.ps1`: хелпер
- HTTP-сервер только на `localhost:43117`. Второй экземпляр сразу выходит, потому что порт занят.
- Трек, позицию и команды он берёт из системной медиа-сессии Windows
  (`GlobalSystemMediaTransportControlsSessionManager`, сессия Spotify).
- Громкость берёт из микшера Windows (Core Audio через `Add-Type` с C# 5).
- Эндпоинты: `/now`, `/cover`, `/cmd?c=toggle|next|prev`, `/seek?ms=`, `/vol?v=0..100`, `/mute?m=0|1`, `/quit`.
- Пишет свой лог `helper.log` рядом с собой (до 256 КБ).

### `SpotifyWeb`: очередь и плейлист
- Медиа-сессия Windows очередь не отдаёт, поэтому используется Spotify Web API.
- Вход идёт через OAuth 2.0 Authorization Code + PKCE с Client ID приложения, которое пользователь создаёт сам;
  секрет не нужен. Ответ принимает временный локальный сервер, который живёт только во время входа.
- Refresh-токен хранится в `PasswordSafe` IDE, access-токен только в памяти.
- Контексты (плейлист, альбом, исполнитель, подкаст) кешируются. Запуск трека из очереди работает только с Premium.

### `Lyrics`: текст песни
- Источник: LRCLIB (`lrclib.net`, без ключа). Сначала `/api/get`, затем `/api/search` по исходному названию
  и по очищенному (без `- Remastered`, `feat.`). Подходящий вариант отбирается по длительности ±8 с.
- Синхронный LRC предпочтительнее простого текста. В кеше 40 ответов. User-Agent без личных данных.

### `LimitsModule`: лимиты Claude
- `GET api.anthropic.com/api/oauth/usage` с OAuth-токеном из `~/.claude/.credentials.json`; это те же данные,
  что `/usage` в Claude Code.
- Токен читается при каждом запросе и больше никуда не уходит. Период опроса задаётся настройкой `interval`.
- На 429 модуль ждёт и повторяет позже; пауза растёт: 1, 2, 4, 8, 15 мин.
- Смена аккаунта: раз в 5 с модуль проверяет время изменения и размер файла входа. Если токен в нём другой
  (сделали `/logout` и `/login`), он сбрасывает паузу после 429 (её заработал прежний вход) и сразу спрашивает
  лимиты заново. Цифры прежнего входа не показываются даже с пометкой «устарело».
- План входа (`subscriptionType` + `rateLimitTier` из файла входа, например «Max 20x») уходит на страницу полем
  `plan` и виден в подсказке бара.

### `RegistryTweaks`: встроенный браузер IDE
Три ключа реестра IDE: `ide.browser.jcef.osr.framerate` (частота кадров),
`ide.browser.jcef.out-of-process.enabled` (браузер в отдельном процессе) и `ide.browser.jcef.gpu.disable`
(без аппаратного ускорения). Это настройки **всей** IDE, они действуют после перезапуска. Меняются только
по кнопкам на странице. «Вернуть как было» сбрасывает их к значениям по умолчанию.

### `PerfJournal`: журнал лагов
- Файл `<system>/cc-gui-tweaks/perf-journal.jsonl`, при 3 МБ ротируется в `.1.jsonl`.
- Источники записей:
  - страница: `frame` (долгий кадр), `stall` (таймер страницы стоял больше 2 с), `page` (минутная сводка);
  - IDE: `edt` (EDT не отвечал на пинг больше 300 мс; дольше 1 с — со стеком EDT);
  - IDE: `min` (раз в минуту процессор IDE и системы, куча, сборка мусора, топ-6 дочерних процессов по процессору).
- **Выгрузка** собирает `~/Downloads/cc-gui-tweaks-logs-<дата>.zip` и открывает папку. В архиве:
  - `summary.txt`: IDE, CC GUI, Java, ОС, реестр, настройки, дочерние процессы;
  - `lags.txt`: журнал по-русски, в читаемом виде;
  - сами jsonl-файлы;
  - `idea-filtered.log`: только относящиеся к делу строки;
  - `jcef/`: хвосты логов Chromium;
  - `freezes/`: последние 3 дампа зависаний IDE.
- Перед записью в архив `scrub()` маскирует `sk-ant-…`, `Bearer …`, пары вида `token=…`/`password=…` и заменяет
  путь к профилю пользователя на `~`.

### `Updater`: обновление без перезапуска
- `build.py install` кладёт JAR в `<config>/cc-gui-tweaks/update/`. Раз в 2 с `Updater` его забирает и вызывает
  штатные `DynamicPlugins.unloadPlugin` и `PluginInstaller.installAndLoadDynamicPlugin`, то же самое, что
  «Install Plugin from Disk».
- Оба вызова уходят в EDT как `Runnable` из `MethodHandleProxies`. Так в стеке выгрузки нет ни одного кадра
  плагина, и старый загрузчик классов ничем не удерживается (иначе IDE потребовала бы перезапуск).
- Лишние старые копии в `plugins/` удаляет уже новая версия при старте.
- Плагин раньше назывался «Spotify Mini for CC GUI» (`local.spotify-mini.ccgui`). Его копии и папки тоже
  убираются, а `build.py` умеет обновлять поверх него.

## `tweaks.js`: страница

Это один IIFE без зависимостей и сборки. Порядок частей в файле:

1. **`send()` и защита от повторного внедрения.** `window.__cctOn` показывает, что скрипт уже стоит. Тогда
   повторное внедрение только заново шлёт `ready`.
2. **`CSS`.** Все стили одной строкой. Цвета берутся из CSS-переменных темы CC GUI
   (`--bg-secondary`, `--text-tertiary`, `--color-chat-bars-*`…) с запасными значениями, поэтому подходят и
   к светлой, и к тёмной теме. Зелёный Spotify: `#1db954`. Состояние модулей задаётся классами на `<html>`:
   `cct-sp-on`, `cct-lim-on`, `cct-sp-min`, `cct-page`, `cct-perf-blur`.
3. **Утилиты:** `esc`, `mmss`, `opt(mod,key)`, `num`, `mk`, `svg`, иконки `ICON`.
4. **`start()` / `stop()` / `tick()`.** `start()` вешает стили, создаёт `window.__cct` с обработчиками и
   таймер `tick` раз в 500 мс. `tick` раз за разом приводит страницу в нужный вид: `placeBars`,
   `spotifyTick`, `queueTick`, `lyricsTick`, `settingsTick`, `perfTick`, `journalTick`. Так CC GUI может как
   угодно перерисовывать свой DOM: на следующем тике элементы встанут на место.
5. **Spotify:** `buildSpotify`, `onSpotify`, `renderSpotify`. Позиция между ответами Java считается локально,
   поэтому полоска движется плавно. Есть перемотка перетаскиванием (`onSeek*`), громкость (`setVolume`) и
   увеличение обложки (`openLightbox`).
6. **Очередь и текст:** `openQueue` / `renderQueue` и `openLyrics` / `renderLyrics` / `lyricsTick`. Обе панели
   всплывают над плеером через общий `placePop`. В тексте текущая строка зелёная и подсвечивается с опережением
   +250 мс. Автопрокрутка встаёт на паузу на 5 с после ручной прокрутки.
7. **Лимиты:** `buildLimits`, `onLimits`, `renderLimits`, `fitLimits` (если подписи не влезают, бар переходит в компактный вид `cct-tight`).
8. **Раздел настроек:** `settingsTick` находит боковое меню настроек CC GUI по частям CSS-модульных имён
   (`[class*="_sidebarItems_"]`) и добавляет туда пункт «CC GUI Tweaks» (`buildNav`). Свою панель `buildPanel`
   он ставит рядом с контентом настроек и копирует его хешированный класс (`tokenLike`), чтобы выглядеть
   «родной». Вкладки описаны в `TABS`, выбранная вкладка хранится в `localStorage` (`cctTab`).
   Переключатели (`toggle(mod,key,label)`) вызывают `change()`, а та шлёт `set:{…}` в Java.
9. **Производительность:** `perfTick` / `perfScan` ищут в самих таблицах стилей страницы правила с
   `animation…infinite` и выключают их своим `<style id="cct-perf">`. Список не устаревает при обновлениях
   CC GUI. Чат рисуется Chromium вне экрана и копируется в окно IDE, поэтому бесконечная анимация означает
   кадры без остановки и нагрузку на процессор.
10. **Журнал лагов:** `jrStart` подписывает `PerformanceObserver` на `long-animation-frame` (в старом Chromium
    на `longtask`).
    - Кадры от 100 мс записываются подробно, не больше 30 в минуту: длительность, блокировка, стили и
      раскладка, три самых долгих скрипта с файлом и позицией.
    - Кадры от 50 мс только считаются в минутной сводке.
    - События уходят пачками в `perflog:` раз в 5 с.
11. **Реестр браузера и «О плагине»:** `renderReg`, `onRegClick`, аватар `AVATAR` (webp в data-URI).

## Как добавить модуль

1. Добавьте ключи с `false` по умолчанию в `Settings.defaults()`.
2. Если нужна работа в IDE, заведите класс модуля с методами `apply()` (запуск или остановка по настройке),
   `onReady(b)` и `stop()`. Вызовите их из `Tweaks.start/stop/onMessage` (`ready` и `set:`).
3. Для своих сообщений добавьте ветку с новым префиксом в `Tweaks.onMessage`, а для данных на страницу —
   новый обработчик в `window.__cct` (`start()` в `tweaks.js`).
4. В `tweaks.js` добавьте вкладку или блок в `buildPanel`, переключатель через `toggle('модуль','ключ',…)`,
   отрисовку в `renderPanel` и свой `…Tick()` в `tick()`. В `stop()` уберите всё, что добавили.
5. Опишите модуль в `dist/Как установить CC GUI Tweaks.txt` и в README.

## Отладка

- Логи плагина пишутся в `idea.log` с префиксом `cc-gui-tweaks:`. После загрузки страницы чата появляется строка
  `скрипт активен в …`.
- Логи хелпера пишутся в `<system>/cc-gui-tweaks/helper.log`.
- Если чат тормозит, включите «Журнал лагов» и потом нажмите «Выгрузить логи».
- `<system>` и `<config>` — это папки IDE, например `%LOCALAPPDATA%\JetBrains\WebStorm2026.3` и
  `%APPDATA%\JetBrains\WebStorm2026.3`.
